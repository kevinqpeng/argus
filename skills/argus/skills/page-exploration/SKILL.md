# 页面探索

## 输入与职责

读取 [共享契约](../../references/contracts.md) 和 [地图、预算与诊断契约](../../references/page-diagnostics.md)。输入为本 run 的批准用例、完整必需矩阵、授权目标及版本、冻结预算、spec 与 caseIds 分配；产物写现有私有 run 路径。

协调者负责探索计划、地图、事件和快照的唯一写入。平台探针沿用 [Web](../../../web-e2e-test/SKILL.md#页面探针) 或 [Mobile](../../../mobile-e2e-test/SKILL.md#页面探针) 的隔离、授权和操作规则；只返回探针回执，不接管阶段调度。本技能不生成业务脚本，不计算业务通过。

## 规划、探测与交接

独立调用按 [工作流组合](../../references/workflows.md) 复用或补齐设计、评审、平台准备与资源规划；只有外部用例时先规范化。只探索时交付全量 check、地图和证据即结束，后续脚本交接仅在调用方选中时执行。平台探针不递归启动完整执行技能。

人工评审通过后、脚本 worker 派发前，协调者一次读取全部批准用例与必需矩阵，按下述契约生成 `evidence/exploration-plan.json`。平台路由在此时完成；Web、Android、iOS 分开规划，纯 API 跳过。UI worker 是现有执行职责，不新增进程或角色。

1. 将每个 UI 用例的每个 step 和 assertion 映射到页面状态、必要元素及矩阵。API/DB 断言或无元素的导航步骤写 `nonUIReason`，仍保留原索引；不能遗漏断言目标。动态需求写 `dynamic=true`，可在到达状态后补充元素，但仍必须关联原用例、受相同预算约束。
2. 运行 `python3 <argus>/scripts/exploration.py plan <私有输入.json>`，保存 stdout；退出 2 或 BLOCKED 停止探索，补齐映射或在授权范围调整预算。脚本按平台、页面、状态、scope 合并需求，校验所有动作/断言×矩阵均有去向，检测未知依赖和依赖环。
3. 按合并任务依赖顺序，只访问需要的页面状态。先查缓存候选，再用必要定位器探针验证；成功即复用，缺失才采集相关区域。相同稳定状态的结构证据仅取一次供多个元素使用。截图仅为明确视觉断言、歧义或必需证据采集。
4. 执行命令前调用 `allow`；结束后立即记录事件，包括失败。协调者独占写计划、地图和事件，worker 只返回独立回执；同一个浏览器页面或 Appium session 串行，禁止先并行检查余额再执行。预算是执行前检查加实际客户端超时，不靠事后统计代替限制。
5. 按 spec 分批就绪：每次地图更新后，对受影响 spec 运行 `check`，`caseIds` 必须等于该 spec 分配的全部用例，`cases` 仍传全部批准用例。检查覆盖这些用例的全部步骤、断言及必需矩阵；PASSED 才释放该脚本任务。无关页面未完成不阻塞已就绪 spec；返回 missing 时仅补充所列元素。动态目标也必须补齐后才能释放对应脚本，不能凭空生成定位器。
6. 脚本 worker 读取本任务不可变的地图快照及其哈希、批准用例、探索计划、check 回执和证据指针；缺信息交协调者，不自行遍历页面。协调者继续探索其他状态，按 [共享调度](../../references/scheduling.md#探索与脚本生成重叠) 及时补位。地图只增补无关条目不使已有快照失效；相关条目失效时停止受影响 worker，保留旧产物并按新计划重新校验、生成，不能修改已发布脚本。用例或预期变化仍回人工评审。
7. 执行前省略 `caseIds` 运行全量 `check`，保存 `scope=all` 的 PASSED 回执，再检查 scripts、discovery 与覆盖门禁。局部 PASSED 只允许生成对应脚本，不能代表全量就绪或业务通过。

## 缺口、失效与完成条件

- 脚本 worker 缺定位信息时，交回受影响 caseIds、页面状态、元素和证据；协调者定点补探并重新 check 后交付新快照。用例或预期变化交回 prd-to-cases 并重新评审。
- 执行失败先按诊断契约分类，仅确认地图失效或允许局部恢复时调用本技能；继承原预算和首次失败证据，不重置预算或自动重放非幂等操作。
- 每个 spec 的完成信号是其全部 caseIds 的 PASSED 回执及不可变地图快照、哈希和证据指针，交给 [脚本生成子技能](../script-generation/SKILL.md)。协调者可继续探索其他页面，不等待全量地图才生成。
- 全量完成要求省略 caseIds 的 check 返回 scope=all、PASSED，覆盖所有 UI 步骤、断言和必需矩阵。纯 API 不采集地图，沿现有 API 路径生成。
- 缺口或预算耗尽保留 partial/BLOCKED 和未完成项；READY、局部 PASSED 及地图完成均不代表业务通过。
