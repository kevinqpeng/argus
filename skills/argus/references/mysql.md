# MySQL 场景核验

数据库路径探索与执行核验分开：生成场景和用例阶段默认不探测数据库、不冻结数据库查询。仅当代码和可用文档无法回答、且授权只读数据库能改变候选路径类型、矩阵分母或待办关系时，主 Agent 才在本 run 派发一个 `exploration` 单例；每 run 最多一个，不与代码探索并行。该任务只读必要表/字段和少量脱敏样本，限制列、行数和时间范围，记录目标环境标识、SQL 摘要及脱敏规则，结果只作为配置证据并进入候选路径 `unknown`/`needs_confirmation`，不自动形成业务预期。未授权、结构不明、版本不匹配或无法安全脱敏时停止并保留缺口。

仅在执行用例时判断是否需要 MySQL 配合；生成场景和用例阶段不探测数据库、不冻结数据库查询。仅对本次授权目标进行核验。按 [MySQL 项目配置](../../setup-argus/references/storage.md#mysql-项目配置) 读取当前 Argus projectDir 中的本机连接；run 冻结 projectId 及非敏感目标指纹，重试和恢复须校验相同目标，禁止静默切换。账号必须由数据库侧限制为目标表或视图的 `SELECT`。数据库只读不承担造数或清理，继续使用业务 API 和既有资源清理规则。配置或授权缺失时相关用例 `BLOCKED`，运行时连接或查询异常为 `ERROR`，不以 API 成功代替必需的数据库断言。

1. 主 Agent 在正式测试执行用例前，依据该用例的验收条件判断是否必须读取数据库状态：验收条件明确要求持久化状态，或用户明确要求数据库断言时需要查库；否则 API/UI 已能充分验证时不增加数据库查询。需求含糊时标记 `needs_clarification`，不要自行加查库。对需要查库的用例绑定 case ID、AC、证据、表与字段；必要时调用 decision-router 的 `mysql_evidence` 对候选核验项作判断。只传脱敏的必要证据。Jev 不负责生成或执行 SQL，明确要求的数据库断言不能被模型否决。
2. 独立 SQL agent 检查当前宿主是否提供专用 MySQL 工具；存在时调用该工具执行核验。没有专用工具时，在 run 私有 harness 使用合适的 MySQL 驱动。冻结目标、业务关联键、经审查的参数化 `SELECT`、预期字段及值、最大行数、轮询间隔和截止时间。表字段和预期须有业务证据；标识符来自审查过的固定模板，用户数据只作为参数。仅允许单条受审查的 `SELECT`；数据库账号也必须受只读权限约束。禁止锁定读、调用存储过程、写文件和其他有副作用的语句。
3. SQL agent 运行时读取私有配置，不输出凭据。验证连接目标和服务身份；设置连接、查询超时和结果上限。用本次业务操作返回的唯一 ID 查询。异步核验每次使用新事务或自动提交读取最新可见状态，直至满足预期或截止；记录读取目标及可能的副本延迟。使用代码精确比较状态、数量、金额等，不让 Jev 判断算术或替代断言。只有已判断需要 MySQL 的用例调用 MySQL 工具；其余用例不发起数据库连接或查询。
4. 每次 attempt 保存脱敏的 case ID、目标标识、查询模板标识、关联键引用、预期、实际、时间、断言和错误；限制敏感数据，禁止密码和完整记录进入日志、Jev 或报告。最终状态不符且预期明确为 failed；目标或凭据缺失为 blocked，运行时连接或查询异常为 error。保留首次失败和重试结果；未执行、缺少证据或连接成功本身均不能通过。

## 主 Agent 调度与验收

- 仅在人工评审及执行前置门禁通过、当前用例确需数据库断言时派发。SQL agent 是独立宿主子 Agent，复用冻结的 reasoning 模型与强度，不新增模型配置角色；直接调用 Web/Mobile 技能、恢复和重试也遵守本流程。宿主无法创建子 Agent 或其无法使用数据库工具/驱动时，相关用例 BLOCKED，主 Agent 或业务 runner 不代做。
- 主 Agent 传入 runId、caseId、matrixId、attempt、taskId/token、projectId、目标指纹、AC、业务证据、唯一业务 ID 引用、查询与预期、截止时间，以及私有配置路径和独占回执路径；凭据由 SQL agent 在本机读取，不进入委派消息。独立任务按 [调度契约](scheduling.md#db-与计时) 执行；串行模式也保留独立 agent，只按依赖顺序启动。
- 业务执行者交付本次操作的唯一 ID 和证据后，主 Agent 才放行后置 SQL 核验。需要前后差值时，SQL agent 在业务操作前采集必要基线，操作后核实差值；两次读取属于正式测试。需要 SQL 核验的业务资源由主 Agent 延后清理，runner 的 fixture teardown 不提前删除这些已登记资源；清理及后续会改变断言状态的操作须等待核验结束；失败时先保存证据，再按既有规则清理。
- SQL agent 将本节任务标识、实际 agent ID、查询模板标识、预期/实际、逐项断言、开始/结束时间、脱敏证据路径和 passed/failed/blocked/error 写入独占 attempt 回执，仅返回核验事实，不改共享结果。主 Agent 校验回执的目标、业务 ID、矩阵、attempt/token 与当前任务一致；旧回执、缺字段或缺证据不得接受，保持未完成并阻断交付。
- 主 Agent 合并业务结果和数据库结果，不新增用例分母、不重复计数。业务断言与全部必需 SQL 断言均 passed 才能通过；明确不符保留 failed，连接/查询异常保留 error，配置/权限/能力缺失保留 blocked；多类问题同时存在时保留各自结果与证据，任一非 passed 均不得汇总为 passed。无需查库仅数据库项 N/A，用例继续执行。队列 completed 仅代表回执已接收，不等于用例 passed。
