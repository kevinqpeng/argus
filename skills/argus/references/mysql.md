# MySQL 场景核验

仅在执行用例时判断是否需要 MySQL 配合；生成场景和用例阶段不探测数据库、不冻结数据库查询。仅对本次授权目标进行核验。按 [MySQL 项目配置](../../setup-argus/references/storage.md#mysql-项目配置) 读取当前 Argus projectDir 中的本机连接；run 冻结 projectId 及非敏感目标指纹，重试和恢复须校验相同目标，禁止静默切换。账号必须由数据库侧限制为目标表或视图的 `SELECT`。数据库只读不承担造数或清理，继续使用业务 API 和既有资源清理规则。配置或授权缺失时相关用例 `BLOCKED`，运行时连接或查询异常为 `ERROR`，不以 API 成功代替必需的数据库断言。

1. 执行用例前，依据该用例的验收条件判断是否必须读取数据库状态：验收条件明确要求持久化状态，或用户明确要求数据库断言时需要查库；否则 API/UI 已能充分验证时不增加数据库查询。需求含糊时标记 `needs_clarification`，不要自行加查库。对需要查库的用例绑定 case ID、AC、证据、表与字段；必要时调用 decision-router 的 `mysql_evidence` 对候选核验项作判断。只传脱敏的必要证据。Jev 不负责生成或执行 SQL，明确要求的数据库断言不能被模型否决。
2. 检查当前宿主是否提供专用 MySQL 工具；存在时调用该工具执行核验。没有专用工具时，在 run 私有 harness 使用合适的 MySQL 驱动。冻结目标、业务关联键、经审查的参数化 `SELECT`、预期字段及值、最大行数、轮询间隔和截止时间。表字段和预期须有业务证据；标识符来自审查过的固定模板，用户数据只作为参数。仅允许单条受审查的 `SELECT`；数据库账号也必须受只读权限约束。禁止锁定读、调用存储过程、写文件和其他有副作用的语句。
3. 运行时读取私有配置，不输出凭据。验证连接目标和服务身份；设置连接、查询超时和结果上限。用本次业务操作返回的唯一 ID 查询。异步核验每次使用新事务或自动提交读取最新可见状态，直至满足预期或截止；记录读取目标及可能的副本延迟。使用代码精确比较状态、数量、金额等，不让 Jev 判断算术或替代断言。只有已判断需要 MySQL 的用例调用 MySQL 工具；其余用例不发起数据库连接或查询。
4. 每次 attempt 保存脱敏的 case ID、目标标识、查询模板标识、关联键引用、预期、实际、时间、断言和错误；限制敏感数据，禁止密码和完整记录进入日志、Jev 或报告。最终状态不符且预期明确为 failed；目标或凭据缺失为 blocked，运行时连接或查询异常为 error。保留首次失败和重试结果；未执行、缺少证据或连接成功本身均不能通过。
