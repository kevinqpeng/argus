# 结构化设置问答

问答由当前宿主 Agent 调用工具完成，host_config.py 只负责配置解析与持久化。不要让用户手写 JSON 或记住 CLI 参数。先读取当前状态、自动发现可用模型和工具，再询问尚未明确的偏好；用户显式传入的设置、已接受的默认值与已有授权不重复询问。只读 doctor 不进入设置问答。

## 每轮选择必须停住

每一轮选择都是阻塞检查点：提出本轮问题后，立即等待实际回答，暂停整个 setup 和调用它的主流程。未回答期间不继续探测、不生成下一轮问题/方案/测试代码、不写配置、不运行测试或发布，也不输出“配置完成”。不把独立工作当作可以继续生成后续内容的理由。

推荐项和默认值只是可选答案，用户明确选择或已经接受“全部采用默认”才可应用。未提交、工具空结果、超时或取消都不算回答；不按等待时长自动选择，不在提问后继续用假定答案把任务做完。

## 工具选择

1. 以本轮实际暴露的工具和最高优先级模式限制为准。先检查 `request_user_input`、`AskUserQuestion` 或宿主提供的等价工具的真实 Schema 与使用条件。不要因当前是 Default 模式、工具名称不同或以往会话不可用而推断本轮不可用。工具存在但当前策略不允许用于本问题时，按不可用处理。
   Codex 当前两种工具的参数不同：同步 `request_user_input` 的问题使用 `header`、`id`、`question` 和对象形式的 `options`；异步 `request_user_input_async` 的问题使用 `title` 和可选的字符串数组 `options`。这是识别差异的提示，实际调用始终以本轮工具 Schema 为准，不混用字段。
2. 本轮允许同步选择工具时，直接调用它并等待真实回答。按 Schema 填写短标题、稳定 ID、问题、选项和影响说明。每轮最多三个独立问题，或遵守更低的宿主限制。推荐项放第一并标注“推荐”。没有多选能力时分步选择。
3. 同步工具不可用，但允许使用异步选择工具时，调用 `request_user_input_async` 或宿主等价工具提出当前问题，然后暂停 setup 和主流程。在实际收到用户回答前，不写配置、不推进后续步骤。若宿主不能在本轮等待，结束本轮并说明正在等待；用户回复后按下方恢复规则继续。控件的默认选项、请求已创建、空结果、超时或取消都不是回答。
   只有真实工具调用成功才可称为已展示选择控件；普通文本、伪造的工具消息或工具请求未成功都不算。异步调用返回后立即结束当前轮，等待用户回复；不得在同一轮继续输出诊断汇总、后续问题或其他执行结果。
4. 工具因参数校验失败时，保留已有回答和当前问题，读取错误与实际 Schema，修正参数并重试。若仍无法调用，检查其他适用的结构化工具；不要把参数错误直接归因于工具不可用。
5. 只有所有适用的结构化选择工具都不存在、被模式或策略禁止，或修正后仍无法呈现选择时，才在最终答复中列出本轮简短编号选项，说明“setup 已暂停，等待你的选择”，并结束本轮。不得虚构工具不可用原因。不要打印仿工具 JSON。
6. 读取实际回答，只补问缺项。不要在同一次响应并排派发后续步骤。名称、链接等自由文本遵守工具实际能力；无适用输入工具时使用最终答复等待。

## 问答顺序

先显示当前 Agent 的 argus-model.json、独立产物目录、可用模型和完整映射表。模型阶段读 [模型与强度规范](models.md)，逐角色列出模型/来源、强度、执行方式与需重选项，再弹选择。按本机单用户使用，不询问姓名、人员 ID 或 profile。

首次提问前完成 setup 第 2 步的 MySQL 配置检查和缺项引导。测试范围尚未明确时，模型选择完成后以结构化选项收集 Web、移动端、两者或仅 API；根据实际回答进入 Playwright 或 Appium 依赖检查。每次提问立即停住，恢复后再执行下一步。

第一轮批量收集彼此独立且用户尚未指定的偏好：

| 问题 | 推荐项及可选项 | 后续处理 |
| --- | --- | --- |
| 采用哪套角色映射？ | 保留/采用上表建议、全部继承当前会话、逐角色自定义 | 候选来自本宿主已发现模型；只在自定义分支问具体角色 |
| 默认推理强度选哪个？ | 本次映射支持的固定档、session（可解析时）、model-default | 每个模型分别校验；不能把上个宿主的强度套过来 |
| 哪些角色单独指定强度？ | 统一默认、指定角色 | 下一轮收集角色和对应支持档位，未指定角色继承 defaultEffort |

映射变化会改变强度候选时，上述问题不是独立问题：先等映射回答，再按新模型问强度。自定义分支只询问选中的角色/模型/强度，保留其余选择。额外输入模型先验证，不能因为用户写了名字就标已可执行；session 无元信息时按执行模式澄清，不能静默改成 high。

模型选择后只补问未明确的保存范围：保存到当前 Agent 的 argus-model.json 或仅本次。Jev 决策内置，Key 缺失时引导用户在宿主安全环境中填写 `TYPESAFE_API_KEY`。已指定 Agent 不重问目录，不提供写入项目/Git 的选项。摘要展示默认强度、完整映射和唯一配置位置，收到选择后才保存。

记录方式按 [通道规范](../../bug-reporter/references/channels.md) 逐层选择，不让用户面对一串技术参数：

1. 问“Bug 记录到哪里？”：在线表格、本地正式表格、在线＋本地。已有可用连接器可推荐在线；没有在线权限/能力时推荐本地。local 是正式交付，不标演练或强制用户先开通服务。
2. 一旦用户选择在线/在线＋本地，下一轮立即按工具选择规则调用真实问答工具，提供“飞书表格”“企业微信表格”两个明确选项；同时可问新建/复用/导入和失败策略。不能只写“请告诉我在线平台和是否新建”，也不能只列一段能力介绍后结束。已有明确的其他通道保留；新用户常规路径先用这两个选项，其他 MCP/API/浏览器/Webhook 方案放到用户明确要求或权限回退分支。
3. 本地分支问 CSV 或 Excel：CSV 可直接打开并有配套脚本；Excel 仅在宿主表格工具可用时承诺生成。显示仓库外保存位置，不询问云端凭据。
4. 询问发布失败时“每次询问（默认）/自动本地记录/停止发布”，保存 delivery.onFailure。无权限且未预选时，用结构化工具给出本地正式交付、换可用在线方式、停止发布；已授权相同回退不重复问。

测试范围、表格位置和附件策略等独立问题每轮仍最多三个。Web 范围确定后，按 [Playwright 安装引导](playwright.md) 检查并在取得授权后安装缺少的依赖。Playwright 的测试目标、角色/租户账号与密码不进入问答；按 [存储规则](storage.md) 告知用户 `projectDir/web-private.json` 的绝对路径和字段模板，由用户自行编辑。只问是否已填好，不读取或回显具体值；公开页面无须账号。项目的 Playwright 配置、.env 和共享账号不能充当默认答案。平台/方式不可用时标待配置，不假装已接通。明确区分在线待补同步与本地已完成。当前任务已经明确本地或两种方式时不重新索要在线单一目标。

每次 setup 都检查 MySQL 配置并按 [项目配置](storage.md#mysql-项目配置) 引导：复用当前 Argus 测试项目的 projectDir；项目不明确时按存储规则选择已有测试项目，不询问项目目录、仓库、PRD 或无关 setup 选项。缺少配置时创建模板并告知绝对路径和缺失字段，由用户本机填写；不在问答中收集或展示密码。配置缺失不阻断非数据库用例，也不表示生成用例时要核验 MySQL。仅配置 MySQL 不触发模型和表格问卷。

每轮提交后立即收集尚缺配置；名称、链接等自由文本也用真实输入工具收集。工具不可用才走上述最终消息暂停路径。环境等缺失值可提供已有值或自定义输入，不要求用户填写内部 ID、JSON 或 CLI 参数。

## Bug 配置的可重跑问题清单

平台、动作、名称/链接、汇总和附件问题统一在 [bug-questions.json](bug-questions.json) 维护。Agent 在仓库外维护 `{schemaVersion:1, answers:{问题ID:实际回答}}`，可带 suggestedTableName；已回答的其他 setup 设置保留，不重复询问。

每轮运行 `python3 <本Skill>/scripts/bug_questions.py <私有状态.json>`。AWAITING_USER 时，将返回的 questions 适配到当前允许的结构化问答工具的实际 Schema 并立即调用，然后等待；不能只向用户打印 JSON 或复制成一段建议。脚本不会代替宿主调用 UI 工具。

读取真实工具结果后，以问题 ID 保存实际值，choiceValues 给出标签映射；脚本也识别定义中的按钮标签。自定义名称/链接保存原文，仅选“粘贴链接/自定义名称”且没有输入内容时保持等待。每轮最多三个问题，依赖上一轮的内容后置。

CHOICES_COMPLETE 只表示选项收集完成，projectOverrides 可交后续保存流程；capabilityStatus=NOT_VERIFIED，仍要检查所选 CLI 的安装/身份/目标权限和实际读回。选择飞书只检测飞书路径，选择企微只检测企微路径；不要安装/授权两套 CLI 来增加无关步骤。高级既有通道明确配置时沿用，不强制改成 CLI。

Jev Key 只通过宿主安全渠道填写，不在问答框索取明文。内置 Jev 从 `TYPESAFE_API_KEY` 读取认证；子 Agent 调用继承宿主现有认证。

回答冲突或无法验证所选模型时，只询问冲突项并按同样检查点停住。取消时保留旧配置并结束本轮；未提交/空回答时保持等待，不自动采用默认，也不跳过该轮。已明确设置不重问，不用重复弹窗催促。

## 回复后的恢复

用户回复后，先对应本轮问题 ID/编号校验答案，只执行该选择允许的分支；后续还需选择时，再按工具选择规则发起下一轮问答并停住。不要一次输出所有后续轮次，也不要把用户的一项回答推断为其他未回答问题的选择。若已存在 manifest，暂停时标 awaiting_user 并保存当前问题/阶段，回复后再恢复；单纯等待不创建新的运行或重跑已完成步骤。

## 写入与结果

全部当前必需选择收到后，再将回答转换为本次覆盖，在已确定范围内执行；已授权的可逆更新不另加审批轮。沿用配置锁、原子写入和不可变快照。结束展示保存位置、实际生效与未验证项；尚在等回答时只展示当前问题，不输出最终配置或完成报告。选择不代表模型切换或服务验证已成功。
