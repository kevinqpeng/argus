# 按复杂度调度影响探索

由宿主执行本流程，复用冻结的 reasoning 角色、模型、强度与预算；不新增角色或后台服务。影响探索在场景冻结前进行，与后续 generation 用例生成分开。项目源码、文档及既有用例只读，不执行业务测试或数据库核验。

## 1. 决定探索方式

主 Agent 先建立初步来源清单、变更对象与需求归属，固定 PRD、契约、HEAD 和纳入的工作区内容快照。检查以下可定位证据，而非按文件数量或需求标题估计复杂度：

- 变更对象有跨业务模块或服务的调用、读写、事件或契约消费者。
- 涉及消息、回调、定时任务，或多个写入者对共享状态进行并发、重试与补偿。
- 多份适用业务规则或接口契约存在冲突，需要分别核查实现和预期。

任一项成立，且至少存在两个可基于当前快照独立读取证据的任务时，启用并行探索。均不成立时单 Agent；依赖证据不足时先继续发现，保留 unknown，不能把未发现当作简单或不相关。复杂但暂不可拆分时先串行追踪至可拆分边界。单 Agent 仍完整执行六维检查，发现上述条件后重新路由。

该规则是调度条件，不给业务结论打分。依赖相关性、规则支持和义务等价等语义判断沿用 decision-router 的集中题目与概率阈值，独立问题批量提交；证据不足先补证据，不以多数票决定事实。

## 2. 派发只读任务

主 Agent 在本 run 的 `cases/exploration.md` 记录方式、依据、来源指纹和任务清单。按业务对象或依赖链拆分；接口调用、数据消费者、异步链路、契约与权限可以成为任务边界，六个维度仍由主 Agent 逐对象核对。每个任务明确任务 ID、起点、负责范围、来源定位、跨任务交接对象和完成条件。所有已知依赖都有负责人；主 Agent 负责尚未归属的边界。

并发数取就绪任务数、宿主可用槽位和冻结预算允许数的最小值。不为凑数量拆分强耦合链路；共享只读输入允许并行。单槽位按相同任务清单串行调度并记录实际方式。配置角色无法调用时遵循模型规范保持 BLOCKED，不能由主会话冒充。

每次派发记录宿主 Agent 标识、任务 ID、attempt、输入指纹、状态与独占回执路径 `cases/exploration/<taskId>/<attempt>.md`。worker 只写该回执，读取完整变更对象索引及相关来源，不修改共享计划、最终影响分析或评审材料。回执逐条包含来源定位、依赖路径、六维归属、当前行为、候选义务、未知项、检索边界与停止依据；业务预期附权威依据，缺失则待确认。边界外发现作为交接项返回，不能以不属本任务为由丢弃。

收到一项结果即核对证据并处理新边界，无需等待整批结束。失败重派前停止旧 worker，增加 attempt 并使用新回执路径；迟到旧结果不合并。预算不足时保留未完成任务和缺口，不减少原范围。恢复时先核对真实 Agent 状态、来源指纹和回执，避免重复派发；来源变化按影响分析规则新建 run。

## 3. 合并与复核

主 Agent 独占最终 `impact-analysis.json`，完成以下检查才进入义务确认和场景冻结：

1. 所有任务完成且回执对应当前输入；逐项核对初始来源、变更对象和六维检查。新增依赖交给已有负责人或建立后续任务，继续到有证据的停止边界。
2. 合并实际依赖和候选义务，保留所有证据引用；同条件、同结果与副作用才可合并义务。冲突回到原始代码或权威契约核查，未解决记 unknown。
3. 对跨任务交接逐条核对生产者、消费者、字段或事件语义及完整路径。任何无人接收的交接或缺回执均为未完成，不用其他任务完成率抵消。
4. 并行探索涉及关键数据、权限或多写入者交错时，由非原作者的 reasoning worker 独立复核该路径与停止依据；主 Agent 汇总差异，缺复核证据保持未知。单 Agent 分支由主 Agent 核对同样边界并如实记录未做独立复核。

在探索记录中保存任务到最终 sourceUnits/checks/obligations 的映射和未完成项。将完成的探索记录及回执以 observation 来源登记到影响分析，记录原始字节哈希并由 evidenceRef/reviewRef 引用；它们仅是探索过程证据，不能代替业务批准。未完成任务、未闭合交接和未解决冲突必须进入 sourceUnits 或 checks，disposition=unknown，使现有覆盖门禁阻断。冻结后不改回执；修改按输入变化处理。

报告实际串行/并行方式、任务完成与缺口、分工/探索/合并/复核的耗时和调用成本。完整墙钟时间包含全部阶段；没有同输入对照实测，不报告提速比例或准确率提升。coverage.py 仍只验证已登记集合，宿主负责核查未登记来源和依赖。
