# 待确认事项

先查已有需求、业务规则、源码或既有测试，再把真正需要业务裁决的问题交给人员。

每条保留业务疑问、已查证据或检索结果，以及不同结论如何影响用例。证据可复用共享来源或材料引用，不要求重复行号清单，也不要求分类、固定字段组合或字数。

最小示例：

```json
{"question":"转办后待办归谁？", "evidence":"已查转办契约，未规定再次提交的归属", "impact":"决定再次提交后待办归属断言"}
```

现有 `sourceRefs`、`searchedRefs`、`evidenceRef` 可继续作为证据；`action`、`conclusion`、`basis`、`impactCaseIds` 可继续说明影响。`disposition` 是可选整理信息：已解决事项可记为 `resolved_by_code`，假设可记为 `assumption`，其余按待裁决呈现。分类不决定材料是否合格。

`notes_check.py` 核对内容非空与可选用例引用存在，不用措辞、字数或字段重复度代替业务判断。明确结论应同步更新相关用例；语义正确性由来源复核及人工评审确认。
